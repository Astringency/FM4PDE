# Reproduction coverage

This review distinguishes three different claims: recomputing published statistics from saved results; running inference again with the original selected model and observations; and training that model again. An archive entry or a saved configuration alone does not establish all three. The machine-readable companion is `REPRODUCTION_COVERAGE.json`.

The original 744 revised and 316 unchanged ablations, and the original 1,056-prediction three-draw study, have actually been recomputed from the server197 archive. Their numerical results agree. New inference has not been run for every historical baseline. Training has not been repeated.

## Exact baseline dependencies

The 48 original main checkpoints occupy 573,544,957 bytes. Their original declared checkpoint hashes all match the current files. After reusing fifteen identical archived files, the new checkpoint copy is 450,678,652 bytes. The 761 metadata files occupy 33,372,614 bytes and include configurations, normalization records, commands, environments, summaries and histories. One is the specifically selected `data_protocol/main_results/full/data_protocol_report.json`; the rest remain under the original `runs` hierarchy. The addendum does not copy the 3 TB evaluations parent tree.

The additional six Burgers checkpoints occupy 49,144,970 bytes. Their 96 evaluation metadata files and 72 checkpoint-neighbor metadata files occupy 1,310,535 and 2,143,836 bytes respectively. None of these six checkpoint hashes duplicates the fifteen reused main-model copies.

`baseline_freeze_plan.json` binds every one of the 186 selected evaluation cells to its original summary/configuration hashes and exact test file, task, sensor seed and mask identity. `freeze_baseline_inputs.py` preserves the native `load_raw` dictionary, including scalar physical metadata, initial fields, original sample IDs and channel names. Eighteen caches cover fifteen main-data branches plus three Burgers distributions. The original loaders cast field arrays to float32; the independent check compares against a fresh read of the original slices after that same cast. The manifest records original MAT SHA, keys/axes/slices, source dtype, each cached tensor's dtype/shape/SHA and exact save/reload checks. It does not describe a derived cache as the original MAT file. All eighteen caches have now passed these checks: 3,935,063,876 cache bytes, derived from fifteen MAT files totaling 94,737,481,264 bytes without copying those files. The final manifest SHA is `feb694a06731452bdae3b10f5bc6812107f7ff481c82b200d22c8e9c8f20f3ba`. Native consumer smoke checks and the separate archival copies are still tracked independently.

`BASELINE_FROZEN_REPLAY.md` documents the native-API consumer. It retains checkpoint normalization and uses the original evaluation settings, rather than treating a source-training configuration as the test configuration. The wrapper uses each run's original baseline commit; agreement of the eight raw-loader functions across those commits does not establish agreement of all model code. FNO/DeepONet also need the recorded native dependencies: the server197 FM environment is not a universal baseline environment.

The following files under `verification_runs/reproduction_coverage/` contain the exact source selections:

- `baseline_all_selected_runs.json`, `selected_baseline_full_summaries.json` and `selected_baseline_effective_configs.json`;
- `burgers_dependencies_and_ns_existing.json` and `burgers_checkpoint_neighbor_metadata.json`;

Final archive destinations and copy/verify receipts are owned by the archive inventory and execution status. A queued addendum is not described here as a completed copy. The original data and result files remain unchanged.

## Remaining boundaries

Six Burgers VIVID evaluation cells trained an inverse operator on 45,000 training and 5,000 validation examples for 20 epochs, but set `save_checkpoint=False`. Their original run directories contain predictions and histories but no learned checkpoint. These saved results remain reproducible as statistics. Recovering the original learned state from frozen test inputs is impossible; rerunning the documented training would be a new training run. The six 4D-Var cells instead use zero training examples and perform per-instance optimization.

The large historical training MAT collections are not copied. Original data paths, source commits, data protocols, split records, normalization, training settings and histories are retained. Repeating training requires those original data or independently validated regeneration, together with the relevant environment. No claim of repeated historical training, bitwise GPU inference equivalence for all methods, or recovered VIVID weights is made.
