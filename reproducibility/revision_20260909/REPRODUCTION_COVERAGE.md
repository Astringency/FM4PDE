# Reproduction coverage

This review distinguishes three different claims: recomputing published statistics from saved results; running inference again with the original selected model and observations; and training that model again. An archive entry or a saved configuration alone does not establish all three. The machine-readable companion is `REPRODUCTION_COVERAGE.json`.

The original 744 revised and 316 unchanged ablations, and the original 1,056-prediction three-draw study, have actually been recomputed from the server197 archive. Their numerical results agree. New inference has not been run for every historical baseline. Training has not been repeated.

## Exact baseline dependencies

The 48 original main checkpoints occupy 573,544,957 bytes. Their original declared checkpoint hashes all match the current files. After reusing fifteen identical archived files, the new checkpoint copy is 450,678,652 bytes. The 761 metadata files occupy 33,372,614 bytes and include configurations, normalization records, commands, environments, summaries and histories. The addendum does not copy the 3 TB evaluations parent tree.

The additional six Burgers checkpoints occupy 49,144,970 bytes. Their 96 evaluation metadata files and 72 checkpoint-neighbor metadata files occupy 1,310,535 and 2,143,836 bytes respectively. None of these six checkpoint hashes duplicates the fifteen reused main-model copies.

`baseline_freeze_plan.json` binds every one of the 186 selected evaluation cells to its original summary/configuration hashes and exact test file, task, sensor seed and mask identity. `freeze_baseline_inputs.py` preserves the native `load_raw` dictionary, including scalar physical metadata, initial fields, original sample IDs and channel names. ## Original Diffusion verification

The five native-precision input caches total 1,049,683,094 bytes. `freeze_diffusion_inputs.py` records full original MAT hashes, exact selected fields/axes/dtypes, small physical metadata and the original IDs 0–999. The NS cache retains `w0` and the final `w` frame with a length-one final axis, together with original time/seed metadata. The native generators therefore retain their original last-frame indexing. Derived caches are identified separately from their source MAT files.

`audit_diffusion_native_inputs.py` then reread all 26,000 saved predictions using these NPZs, without reading the MATs again. It verified each original mask and compared every field relative-L2 to a saved reference: 19,000 metric JSON records and 7,000 original final-loss records. The largest absolute discrepancy was 2.6646e-14, below the declared tolerance (rtol 2e-7, atol 1e-10). Where an observation-relative-L2 reference existed, the largest discrepancy was 1.7764e-15. All 26 cells have exactly 1,000 examples; `diffusion_full_cell_summary.csv` records means and sample SD (ddof=1), in ratios rather than percentages, plus observation MSE. The complete audit took 58.9 seconds on two CPU threads and did not initialize CUDA. Numerical checks stopped after this complete pass.

The original pickle and available metric hashes are retained for all examples in `per_example_checks.json.gz` (SHA `c6225bdce35750fa51f5828577fa3b44804709a428b9078ab4ce2f8bccebb1d0`). The final validation SHA is `2f5b87038ee657c5a9ca44995e6ed4ea339d7d61da9c5795b07094b8aa999941`; the frozen-input manifest SHA is `818bdbfc3c7e4888110f92eda0fd1a2d9bf5e5fbe98874c749ee80f3eff04f15`. A separate archive association check passed for all 26,000 pickle files and 19,000 available metric JSON files: every path and SHA matches the already verified server197 archive receipt. The fifty observed-field mask groups each contain 1,000 examples, with mask shape/dtype/count and ordered hash-sequence summaries. Its final report SHA is `9f8809ac375b9e34f685064fedcc4212953ea142db6fb19d4bbd612156f60562` (`diffusion_archive_binding_validation.json`).

`DIFFUSION_INPUT_REPLAY.md` documents the completed native materialization interface. Five compact MAT/HDF5 files were reread in full with identical arrays and dtypes; the original generator loading statements agreed at indices 0, 17 and 999 for all five PDEs. No model was loaded or sampled. Independent review also matched all 26 original configuration hashes to the verified result archive, all generated configuration hashes to the report, all five extracted loading functions to the captured source AST, and all five selected checkpoint hashes to the verified selected-model archive receipt. Numerical settings remain unchanged; only data, weight and new output paths are replaced. The resulting 1.05 GB native input view is reproducibly derived from the NPZs and need not be archived twice. The report and `diffusion_materialization_independent_review.json` retain this evidence. New inference must use the documented native CLI, including its observation-guidance handling, and must check original masks before claiming identical observations.

Whole-MAT hash comparison also establishes an important historical distinction: the four non-Burgers native files equal the corresponding baseline Smooth sources, whereas the old native Burgers file equals the baseline **ID** source despite its filename lacking `_id`. These old Burgers outputs are distinct from the new frozen-input Burgers comparison and do not replace its published values.

The old FM main runs explicitly record eight source commits in 2,892 selected `run_metadata.json` files; the baseline summaries record seven evaluation commits across 186 cells. Exact mappings and metadata hashes are in `old_fm_actual_source_commits.json` and `baseline_actual_evaluation_commits.json`. The original Diffusion configs/pickles/metrics do **not** record their producer HEAD. The current clean `151e721` checkout and historical `d494d733`/`2eb3c94` trees are saved as source history; they are not presented as a proven original run identity. This boundary remains even though the input/output numerical correspondence now passes fully.

## Remaining boundaries

Six Burgers VIVID evaluation cells trained an inverse operator on 45,000 training and 5,000 validation examples for 20 epochs, but set `save_checkpoint=False`. Their original run directories contain predictions and histories but no learned checkpoint. These saved results remain reproducible as statistics. Recovering the original learned state from frozen test inputs is impossible; rerunning the documented training would be a new training run. The six 4D-Var cells instead use zero training examples and perform per-instance optimization.

The large historical training MAT collections are not copied. Original data paths, source commits, data protocols, split records, normalization, training settings and histories are retained. Repeating training requires those original data or independently validated regeneration, together with the relevant environment. No claim of repeated historical training, bitwise GPU inference equivalence for all methods, or recovered VIVID weights is made.
